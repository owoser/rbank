# HTTP 管理 API

面向运维脚本与监控的内置管理接口。它只覆盖**管理域**：查询、改配置、调汇率、冻结卡、裁决异常单据。**不开放玩家存取转**——资金动作只能走游戏内的指令与表单，避免第二套入口出现两套校验。

下文所有示例假定：

```bash
export RBANK=http://127.0.0.1:8089
export RBANK_TOKEN='至少 32 个字符的管理令牌'
```

## 开关与鉴权

接口默认关闭。在某一服的 `config/config.json` 打开即可，其余服无需开启：

```json
"http": {
  "enabled": true,
  "host": "127.0.0.1",
  "port": 8089,
  "token": "至少 32 个字符的管理令牌"
}
```

- `enabled` 为真时 `token` 必须至少 32 字符，否则插件拒绝加载。
- 绑定失败（端口占用、地址不可用）会让插件启动失败，而不是静默降级。
- 监听在独立线程，工作线程池上限 32，单请求体上限 16 KiB，读写超时各 3 秒。
- 令牌按常量时间比较，不通过响应时间泄露前缀。

所有请求必须带 `Authorization: Bearer <token>`，缺少或错误一律返回 `401`：

```json
{"code":"AUTH","message":"Admin token is required","data":null}
```

## 通用响应

所有响应都是同一个信封，`Content-Type: application/json; charset=utf-8`：

```json
{"code":"OK","message":"","data":{}}
```

| 字段 | 说明 |
|---|---|
| `code` | `OK` 表示成功，其余为业务错误码（见下表） |
| `message` | 面向运维的英文说明，固定英文，不随玩家语言变化 |
| `data` | 成功时的载荷；失败为 `null` |

| HTTP 状态 | 条件 |
|---|---|
| `200` | `code == "OK"` |
| `401` | 鉴权失败 |
| `503` | `code == "UNAVAILABLE"`（数据库不可用、银行维护中） |
| `400` | 其余业务失败（参数错误、目标不存在、状态冲突等） |

常见错误码：

| code | 含义 |
|---|---|
| `AUTH` | 令牌缺失或错误 |
| `INPUT` | JSON 无法解析或字段类型不对 |
| `CONFIG` | 配置内容不合法 |
| `CARD` / `FROZEN` | 卡不存在 / 已冻结 |
| `NODE` | 节点不存在或身份不一致（此时银行整体只读） |
| `RATE` | 汇率必须为正整数 |
| `INTENT` | 单据不存在，或状态不是 `ORPHAN` |
| `TAKEN` | 该操作已被其他执行者处理（CAS 失败） |
| `UNAVAILABLE` | 数据库不可用或银行维护中 |

## 读接口

### `GET /v1/cards/{xuid}`

玩家的卡列表。`xuid` 必须是纯数字、非零、不超过 20 位。

```bash
curl -s "$RBANK/v1/cards/2535412345678901" \
  -H "Authorization: Bearer $RBANK_TOKEN"
```

```json
{"code":"OK","message":"","data":[
  {"card_no":"A1QV7M3KP9RT","slot":0,"balance_base":1250,"status":"ACTIVE"}
]}
```

无卡时 `code` 为 `EMPTY`（HTTP 400），`message` 为 `No bank card opened yet`。

### `GET /v1/ledger/{xuid}`

最近 100 条银行域流水，按时间倒序。

```bash
curl -s "$RBANK/v1/ledger/2535412345678901" \
  -H "Authorization: Bearer $RBANK_TOKEN"
```

```json
{"code":"OK","message":"","data":[
  {"kind":"DEPOSIT","delta_base":100,"fee_base":1,"balance_after":1250,
   "rate":100,"server_id":"server-a","created_at":1762900000}
]}
```

`created_at` 是 Unix 秒。`rate` 是当时快照，之后调汇率不影响历史。

### `GET /v1/nodes`

所有已登记节点及其最近心跳。

```bash
curl -s "$RBANK/v1/nodes" \
  -H "Authorization: Bearer $RBANK_TOKEN"
```

```json
{"code":"OK","message":"","data":[
  {"server_id":"server-a","name":"Server A","currency":"Coin",
   "status":"ONLINE","heartbeat":1762900000}
]}
```

`heartbeat` 超过 300 秒即为离线：归属该节点的未结单据会在恢复扫描时被标记 `ORPHAN`。

### `GET /v1/rates`

各服当前生效汇率，即 `effective_at <= now()` 的最新一条。

```bash
curl -s "$RBANK/v1/rates" \
  -H "Authorization: Bearer $RBANK_TOKEN"
```

```json
{"code":"OK","message":"","data":[
  {"server_id":"server-a","rate":100,"effective_at":1762900000,"set_by":"admin"}
]}
```

`rate = 本服货币 / 基准单位`，恒为正整数。

### `GET /v1/config`

当前热配置（角色 `bank`）。字段与 `PUT /v1/config` 一致。

```bash
curl -s "$RBANK/v1/config" \
  -H "Authorization: Bearer $RBANK_TOKEN"
```

```json
{"code":"OK","message":"","data":{
  "slots":1,
  "base_unit":"Base",
  "deposit_fee":{"ppm":10000,"fixed":0},
  "cross_fee":{"ppm":10000,"fixed":0},
  "transfer_fee":{"ppm":10000,"fixed":0},
  "max_single_base":1000000000,
  "max_daily_base":10000000000,
  "enabled":true,
  "deposits":true,
  "withdrawals":true,
  "transfers":true,
  "join_form":true
}}
```

| 键 | 说明 |
|---|---|
| `slots` | 每名玩家的卡槽上限，1–100 |
| `base_unit` | 基准单位显示名，1–24 字符、不含换行制表符，默认 `Base` |
| `deposit_fee` / `cross_fee` / `transfer_fee` | `ppm`（百万分之一，0–1000000）+ `fixed`（固定额，基准单位） |
| `max_single_base` | 单笔限额（基准单位） |
| `max_daily_base` | 日限额（基准单位），不得小于单笔限额 |
| `enabled` | 总开关，关闭后银行整体维护中 |
| `deposits` / `withdrawals` / `transfers` | 分功能开关 |
| `join_form` | 入服是否自动弹卡面板 |

### `GET /v1/intents/{id}`

单据详情，`id` 为 32 位小写十六进制。

```bash
curl -s "$RBANK/v1/intents/8f14e45fceea167a5a36dedd4bea2543" \
  -H "Authorization: Bearer $RBANK_TOKEN"
```

```json
{"code":"OK","message":"","data":{
  "intent_id":"8f14e45fceea167a5a36dedd4bea2543",
  "xuid":"2535412345678901",
  "card_no":"A1QV7M3KP9RT",
  "direction":"WITHDRAW",
  "state":"ORPHAN",
  "base_amount":100,
  "fee_base":1,
  "local_amount":10000,
  "rate":100,
  "server_id":"server-a",
  "attempts":0,
  "error":"unconfirmed LegacyMoney call or offline owner"
}}
```

`state` 取值：`PENDING_LEGACY`（等待原版确认）、`PENDING_DB`（原版已确认、等待入账）、`SETTLED`、`ROLLED_BACK`、`ORPHAN`。

## 写接口

### `PUT /v1/config`

整体替换热配置。请求体必须是完整的配置对象，缺键或不合法即拒绝，不会做部分更新。推荐先 `GET /v1/config` 取回、改完再整个提交：

```bash
curl -s "$RBANK/v1/config" -H "Authorization: Bearer $RBANK_TOKEN" > cfg.json
# 编辑 cfg.json 中的 base_unit
curl -s -X PUT "$RBANK/v1/config" \
  -H "Authorization: Bearer $RBANK_TOKEN" \
  -H "Content-Type: application/json" \
  --data @cfg.json
```

等效的单次调用：

```bash
curl -s -X PUT "$RBANK/v1/config" \
  -H "Authorization: Bearer $RBANK_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"slots":2,"base_unit":"Base","deposit_fee":{"ppm":10000,"fixed":0},
       "cross_fee":{"ppm":10000,"fixed":0},"transfer_fee":{"ppm":10000,"fixed":0},
       "max_single_base":1000000000,"max_daily_base":10000000000,
       "enabled":true,"deposits":true,"withdrawals":true,"transfers":true,"join_form":true}'
```

```json
{"code":"OK","message":"","data":{
  "slots":2,
  "base_unit":"Base",
  "deposit_fee":{"ppm":10000,"fixed":0},
  "cross_fee":{"ppm":10000,"fixed":0},
  "transfer_fee":{"ppm":10000,"fixed":0},
  "max_single_base":1000000000,
  "max_daily_base":10000000000,
  "enabled":true,
  "deposits":true,
  "withdrawals":true,
  "transfers":true,
  "join_form":true
}}
```

写入者记为 `http-admin`，版本号自增；各节点在下一轮维护（30 秒内）读到新值，无需重启。

`base_unit` 只改显示名，不改记账精度：卡余额、批次、限额、费率仍以整数基准单位存储，已有数据不受影响。改名前后的历史流水共用同一套数字。

它也可以不经过 HTTP 修改：`/rbank baseunit set <名称>`（OP）走同一个字段与同一份校验。两者都是整对象覆盖，都会把写入者记为 `http-admin` / 执行者 XUID，且只对**发起写入的那个节点**立即生效，其余节点在自己的维护循环里（最长 30 秒）收敛。

### `POST /v1/cards/{card_no}/freeze`

冻结或解冻一张卡。冻结只影响存取转，不影响查询与余额。

```bash
curl -s -X POST "$RBANK/v1/cards/A1QV7M3KP9RT/freeze" \
  -H "Authorization: Bearer $RBANK_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"frozen": true}'
```

```json
{"code":"OK","message":"","data":{"card_no":"A1QV7M3KP9RT","status":"FROZEN"}}
```

### `POST /v1/rates`

为指定服务器追加一条汇率记录，立即生效并全服广播公告。`rate` 必须为正整数；`server_id` 必须已在 `node` 表中登记。

```bash
curl -s -X POST "$RBANK/v1/rates" \
  -H "Authorization: Bearer $RBANK_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"server_id": "server-a", "rate": 100}'
```

```json
{"code":"OK","message":"","data":{"server_id":"server-a","rate":100}}
```

调汇率不会冻结存取。下调前必须先公告并预判存量：玩家可以「调高前存入、调低前取出」，套利空间由运营纪律承担。

### `POST /v1/intents/{id}/resolve`

裁决一张 `ORPHAN` 单据，`legacy_applied` 表示原版侧那笔调用是否实际生效。

```bash
curl -s -X POST "$RBANK/v1/intents/8f14e45fceea167a5a36dedd4bea2543/resolve" \
  -H "Authorization: Bearer $RBANK_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"legacy_applied": true}'
```

```json
{"code":"OK","message":"","data":{"intent_id":"8f14e45fceea167a5a36dedd4bea2543"}}
```

| 单据方向 | `legacy_applied` | 处理 |
|---|---|---|
| `DEPOSIT` | `true` | 前滚入账 |
| `DEPOSIT` | `false` | 标记 `ROLLED_BACK` |
| `WITHDRAW` | `true` | 标记 `SETTLED` |
| `WITHDRAW` | `false` | 补偿回滚银行侧 |

非 `ORPHAN` 状态返回 `INTENT`；被其他执行者抢先处理返回 `TAKEN`。**裁决前务必先查原版侧的真实结果**——判错会造币或多扣。

## 排障流程

1. `GET /v1/nodes` 看节点心跳与状态；节点离线会让其单据在宽限期后变 `ORPHAN`。
2. `GET /v1/intents/{id}` 读 `state` 与 `error`，`error` 记录了最后一次状态迁移的原因。
3. 对照原版经济日志确认那笔 `Add` / `Reduce` 是否发生。
4. `POST /v1/intents/{id}/resolve` 裁决。
5. `GET /v1/ledger/{xuid}` 复核流水与余额。
